  app/operador/page.tsx:105 ....... <header> com logo + e-mail + "Sair"

Origem do nome: como o operador é provisionado direto no Supabase Auth, o
único lugar possível para o nome é o `user_metadata` do usuário. Por isso a
leitura aceita várias chaves e o e-mail permanece como fallback.

6. PONTOS EM ABERTO
====================================================================
- O nome só aparece se o usuário do Supabase Auth tiver `nome` (ou full_name /
  name / nome_completo / display_name) no user_metadata. Hoje, pelo print, a
  conta em uso não tem — por isso o cabeçalho continuará mostrando o e-mail
  até alguém preencher o campo. Isso é feito no dashboard do Supabase
  (Authentication → Users → o usuário → User Metadata) ou por API. Se
  preferir, dá para criar uma tabela `operadores.nome` e ler de lá.
- A allowlist `operadores` já existe (usada em proxy.ts) e seria o lugar
  natural para guardar o nome do parceiro, se o negócio quiser gerenciar isso
  fora do painel de autenticação.
- O cabeçalho agora é um componente reaproveitável: se surgirem outras telas
  logadas do operador, é só montar o mesmo <OperadorHeader>.
